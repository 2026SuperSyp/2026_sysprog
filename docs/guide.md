## 11/24에 바뀐 것 (스테이지를 만드는 사람은 꼭 읽기)

**할 일**

1. `git pull`로 `main`을 받는다.
2. 올리기 전에 `make test-stage STAGE=내스테이지 BRAIN=real`을 돌려 "통과"를 본다. 서버에서, 진짜 뇌로 2라운드를 끝까지 도는지 보는 검사다.
3. 빌드가 "스테이지에서 쓰면 안 되는 함수를 부릅니다"에서 멈추면, 적힌 함수(`rand`, `time`, `sleep` 등)를 `stage_rng_*`나 틱 수로 바꾼다.

**진짜 뇌는 가짜 뇌와 다르게 반응한다.** 발표는 진짜 뇌로 한다. 가짜 뇌에서 맞춘 수치가 그대로 통하지 않는 곳이 있다(표는 아래 "가짜 뇌와 진짜 뇌의 차이").

- 음식 골라 먹기: 단맛이 1.0이면 짠맛을 줘도 먹는다. 단맛을 0.5쯤으로 낮춰 같이 주면 짠맛이 통한다. 물로는 먹게 할 수 없다. 쓴맛은 그대로 통한다.
- 파리채 피하기, 플래핑 플라이: 진짜 뇌는 다가옴 0.3부터 달아난다(가짜 뇌는 0.5부터). 가짜 뇌에서 "아슬아슬하게 안 달아나는" 세기는 진짜 뇌에서 달아난다.
- 모든 스테이지: 진짜 뇌는 반응이 2~3틱 늦다. 자극을 한 틱만 주면 반응하지 않을 수 있으니 몇 틱 이어서 준다.
- 냄새(`BR_ODOR_*`, `BR_REPEL_*`)는 두 뇌 모두 반응하지 않는다.
- 직접 보려면 `make brain-table BRAIN=real`.

**그 밖에**

- 라운드가 끝나면 보스전이 이어진다(살아남은 사람이 초파리와 싸운다). 스테이지 코드와는 무관하다.
- 헤더 네 개(`stage.h`, `brain.h`, `ui.h`, `screen.h`)는 바뀌지 않았다.
- 스테이지의 조작은 WASD로 안내한다. 코드는 그대로다. 자주 나온 질문의 답은 아래 "자주 묻는 것"에 모았다.

## 준비

```
wsl --install -d Ubuntu-24.04          (윈도우에서 한 번만)
sudo apt install build-essential git   (우분투에서 한 번만)
```

코드는 우분투의 홈 폴더(`~/`)에 둔다. 윈도우 쪽 폴더에 두면 느리고 경로 문제로 빌드가 깨질 수 있다.

## 터미널 크기

게임 화면은 가로 240칸, 세로 67줄 이상이 필요하다. 터미널을 최대화하고 `Ctrl`+`-`를 몇 번 눌러 글자를 줄인다. `stty size`를 쳤을 때 `67 240` 이상이면 된다. 모자라면 게임 대신 안내가 뜬다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `make run STAGE=example` | 스테이지를 실행한다. 왼쪽이 초파리, 가운데가 나다. 오른쪽 위에는 무작위로 움직이는 다른 참가자 한 명이 보이고 `Tab`으로 바꾼다. 마지막 사람 다음에는 키보드를 치는 초파리가 나온다. 오른쪽 아래는 초파리 뇌 표시다. `q`로 나간다 |
| `make run STAGE=example SEED=7 PLAYERS=1 BRAIN=slow` | 같은 문제로 다시, 한 명만, 느린 가짜 뇌로 |
| `make bot STAGE=example` | 화면 없이 여러 판을 돌려 검사한다. "통과"가 나와야 한다 |
| `make screen SCREEN=lobby CASE=2` | 화면 하나를 예시 상태로 띄운다(`lobby`, `result`, `ranking`, `spectate`). 아무 키나 누르면 끝난다 |
| `make log STAGE=example` | 스테이지의 `printf` 출력과 경고를 본다 |
| `make test-fail` | 서버가 고장 상황을 버티는지 본다(스테이지 죽이기, 접속 끊기, 잘못된 메시지 등 10가지). 서버 코드를 고친 뒤에 돌린다 |
| `make termbench` | 이 터미널이 초당 20장을 따라오는지 잰다. 도는 동안 마우스를 움직이면 마우스 보고도 확인한다 |
| `make run STAGE=example BRAIN=real` | 진짜 초파리 뇌 배선으로 돌린다. 아래 "진짜 뇌"의 준비를 먼저 한다 |
| `make test-stage STAGE=example` | 그 스테이지가 서버에서도 도는지 본다(서버와 봇 2명으로 2라운드). 올리기 전에 돌린다. `BRAIN=real`도 된다 |
| `make brain-table` | 자극의 세기별로 뇌의 반응을 표로 본다. `BRAIN=real`이면 진짜 뇌의 표도 나온다 |
| `make bossbot` | 보스전 계산부(`boss/`)를 화면 없이 여러 판 돌려 전략별 승률을 표로 본다. 수치는 `boss/config.ini`에 있다. `BRAIN=real`이면 진짜 뇌로도 돌린다 |
| `make release` | 발표용 빌드를 `build/release/`에 만든다. 메모리 검사 없이 최적화해서 빠르다. 다른 명령에도 `MODE=release`를 붙이면 그 빌드로 돈다(예: `make server MODE=release`). 만들고 검사할 때는 기본(`build/dev/`)을 쓰고, 발표할 때만 release를 쓴다 |

## 여러 명이 같이 하기

서버 한 대에 클라이언트가 접속한다. 3명까지 참가자이고 그 뒤로 들어온 사람은 관전자다.

```
make server ORDER=example            (서버. ORDER에 스테이지 이름을 쉼표로 적는다)
make client HOST=서버주소 NAME=이름  (접속. 같은 컴퓨터면 HOST를 빼도 된다)
make demo-local                      (한 컴퓨터에서 서버, 봇 2명, 나 1명으로 한 판)
```

- 다른 컴퓨터에서 접속하려면 서버 컴퓨터에 설정이 필요하다. `docs/network.md`를 본다.
- 클라이언트는 입장 화면부터 뜬다. 방향키로 고르고 스페이스나 엔터, 또는 숫자 키: 1 입장, 2 지난 랭킹, 3 나가기. 지난 랭킹은 로비에 들어가지 않고 순위만 받아 온다.
- 로비에서 스페이스로 준비하고, 모두 준비되면 방장(가장 먼저 들어온 사람)이 F를 눌러 시작한다.
- 흐름: 로비 -> 규칙 설명 3초 -> 3, 2, 1, GO -> 게임 20초 -> 판정 -> (4라운드 반복) -> 보스전(키 안내 5초, 싸움 3분, 결과 3초) -> 랭킹 -> 로비.
- 서버는 라운드마다 스테이지 실행 파일(`build/dev/stage_이름`)을 따로 띄운다. 자기 실행 파일 옆의 것을 띄우므로 `build/release/server`는 `build/release/`의 스테이지와 뇌를 쓴다. 스테이지 코드는 `make run`일 때와 같다.
- 스테이지의 `printf` 출력은 `build/logs/stage_이름.log`에 쌓인다.
- 한 판이 끝나면 참가자의 누적 점수가 `data/ranking.txt`에 한 줄씩 쌓인다(`이름 점수 시각`). 역대 10위까지가 로비와 랭킹 화면에 나온다. 서버를 `--ranking=파일`로 띄우면 다른 파일을 쓴다. 파일의 꼴은 `core/ranking.h`에 적혀 있다.
- 서버는 초파리 뇌를 따로 뜬 프로세스(`build/dev/brain_proc`)에서 계산한다. 뇌가 죽거나 멈추면 서버가 다시 띄우고, 그동안 초파리는 직전 반응을 유지한다. 뇌의 로그는 `build/logs/brain.log`에 쌓인다. `make run`과 `make bot`은 전처럼 스테이지 안에서 계산한다.
- 뇌가 뜨지 못해도 판은 이어 간다. `BRAIN=real`인데 자료가 없어 준비되지 못하거나, 판 도중에 3번 연달아 제대로 뜨지 못하면 서버가 규칙으로 움직이는 뇌(`fast`)로 바꾸고 로그에 한 줄 남긴다. 그때부터 오른쪽 아래 뇌 표시도 점 격자로 바뀐다. 바꾸지 말고 서버를 멈추게 하려면 서버에 `--brain-strict`를 준다. 검사는 `sh tests/fallback.sh`(`make test`에 들어 있다).
- 들어온 뒤 10초 동안 아무것도 보내지 않는 접속은 서버가 끊는다. 클라이언트는 2초마다 알리므로 로비에서 가만히 있어도 끊기지 않는다.
- 보스전 도중에 누가 나가거나 뇌가 죽어도 판은 끝까지 간다(`sh tests/boss.sh`, `make test`에 들어 있다). 쓰러졌거나 관전 중이면 `Tab`으로 볼 사람을 바꾼다.
- 보스전에 들어간 사람은 모두 체력 3으로 시작한다. 미니게임에서 남은 기회는 누가 보스전에 가는지만 정한다(기회를 그대로 체력으로 주면 한두 판 진 사람들로는 이길 수 없었다).
- 보스전은 키 안내를 5초 보여 준 뒤에 시작한다. 싸우는 동안에는 `H`로 다시 볼 수 있다. 조작은 아래 "보스전 조작"에 있다.
- 보스전이 끝나면 결과(초파리를 잡았다, 시간이 다 됐다, 모두 쓰러졌다)를 3초 보여 준 뒤 랭킹으로 간다.
- 화면을 터미널에 보내는 방법은 둘이다(픽셀 그림, 글자 칸). 클라이언트가 터미널에 물어보고 고른다. 크게, 좋게 보는 법은 아래 "화면을 좋게 보기"에 있다.

## 보스전 조작

| 키 | 하는 일 |
|---|---|
| `W` `S` (또는 `↑` `↓`) | 한 걸음 앞, 뒤 |
| `A` `D` | 왼쪽, 오른쪽으로 옆걸음. 시선은 그대로다 |
| 마우스를 좌우로 (또는 `←` `→`) | 시선 돌리기. 마우스가 화면 양 끝에 있는 동안은 계속 돈다 |
| 왼쪽 클릭 또는 `E` | 고른 무기 쓰기 |
| `스페이스` | 뛰어오르기. 0.5초 동안 떠 있다(높이 1칸). 돌진이 닿는 순간에 0.35칸 이상 떠 있으면 돌진이 발밑으로 지나가서 맞지 않는다. 막기와 달리 초파리는 멈추지 않는다. 내려서기 직전(0.15초 안)에 또 누르면 내려서자마자 다시 뛴다 |
| `R` 또는 오른쪽 클릭 | 막기. 0.5초 동안 막는 자세를 한다. 그동안 돌진에 닿으면 다치지 않고 초파리가 1.2초 멈춘다. 한 번 쓰면 2.5초 뒤에 다시 쓸 수 있다 |
| `C` | 살금살금 켜고 끄기. 켜 두면 걸음이 짧아지고 초파리가 뛰어 달아나지 않는다 |
| `Shift`와 함께 이동 | 그 걸음만 살금살금 |
| `1` `2` `3` `4` | 파리채, 스프레이, 끈끈이, 먹이 고르기 |
| `F` 또는 마우스 휠 | 다음 무기 |
| `Tab` | 쓰러진 뒤나 관전 중에 다른 사람의 눈으로 보기 |
| `H` | 키 안내 켜고 끄기 |
| `Q` | 나가기 |

- 화면에서는 진행자 시프봇이 알려 준다. 시작하기 전 5초 동안, 그리고 `H`를 누를 때마다 시프봇이 말풍선으로 키를 전부 보여 준다. 싸우는 동안에는 3D 화면 왼쪽 아래의 짧은 안내와 아래 상태 줄의 무기 앞 숫자가 늘 보인다. 살금살금이 켜져 있으면 안내의 그 글자와 가운데 표시가 하늘색이 된다.
- 3D 화면의 왼쪽 위에 초파리 뇌가 나온다. 미니게임 화면의 뇌 표시와 같은 그림이다(진짜 뇌이면 뇌 지도). 그 아래의 "자극"은 내가 다가가서 초파리에게 주는 다가옴 자극이고, "도약"은 뇌의 달아남 반응이다. 도약 막대가 세로줄을 넘으면 초파리가 뛰어올라 달아난다. 걸어서 다가가면 막대가 오르고 살금살금 다가가면 낮게 머문다.
- 시선은 클라이언트가 정한다. 마우스가 가로로 움직인 만큼 바로 돌려 그리고 서버에는 결과인 방향만 알린다. 서버를 거쳐 돌아온 방향으로 그리면 한두 틱(50~100ms) 늦는다. 터미널은 마우스를 가둘 수 없어서 화면 끝에서 더 못 움직이므로, 끝에 닿아 있는 동안은 계속 돌게 했다. 수치는 `core/client.c`의 `LOOK_*`에 있다(화면 너비만큼 움직이면 200도).
- 살금살금을 켜고 끄는 키를 따로 둔 까닭: 터미널은 키를 뗀 것을 알려 주지 않고, Windows Terminal은 Shift를 누르고 있는 동안의 마우스를 글자 선택에 쓰는 것으로 알고 있다(직접 재 보지는 않았다). 그러면 Shift를 누른 채로는 시선을 돌릴 수 없다.
- 조작을 바꾸면 `boss/boss_view.c`의 `draw_guide`, `draw_legend`, `boss/boss_view_hd.c`의 `draw_hint`와 이 표를 같이 고친다.
- 초파리의 체력은 참가자 수마다 따로 정한다(`boss/config.ini`의 `fly_hp_1`, `fly_hp_2`, `fly_hp_3`: 40, 120, 180). 여럿이면 초파리를 에워싸서 한 사람 몫보다 훨씬 빨리 깎으므로 사람 수에 비례하지 않는다. 쉬지 않고 붙는 봇으로 재면 한 판이 20초에서 1분쯤이다(`make bossbot BRAIN=real`). 전에는 참가자 수 x 80에 맵도 넓어서 대부분 제한 시간 3분을 다 썼다.
- 초파리가 달아나느라 솟아오른 동안(0.5초)은 파리채가 닿지 않는다. 스프레이와 끈끈이는 닿는다.
- 먹이(4번, 참가자마다 3개)를 쓰면 보는 쪽 3칸 앞에 놓인다. 초파리는 8칸 안에 보이는 먹이로 걸어오고, 닿으면 단맛 자극이 뇌로 들어간다. 뇌의 먹기 반응이 기준(0.5)을 넘으면 그 자리에 내려앉아 먹는다(다 먹는 데 3초). 먹는 동안에도 다가옴 자극이 세면 뇌의 달아남 출력이 먼저 켜져서 뛰어오르므로, `C`로 살금살금 다가가야 때릴 수 있다. 맞으면 먹이를 버리고 5초 동안 먹이를 찾지 않는다. 다 먹게 두면 체력이 5 돌아온다. 먹이로 가는 동안에는 돌진하지 않는다.
- 여기서 뇌가 정하는 것은 "먹을지"와 "달아날지"다. 진짜 뇌에서 단맛 자극은 단맛을 느끼는 뉴런들이고 먹기 반응은 주둥이를 내미는 운동 뉴런이다. 먹이 쪽으로 걸어가는 것은 계산부의 규칙이다(이 뇌 모델에는 냄새를 따라 도는 입력을 넣지 않았다).
- 왼쪽 위의 뇌 표시에 단맛과 먹기 막대, 그리고 초파리가 지금 하는 일(돌아다님, 경계, 달아남, 돌진, 먹이로 감, 먹는 중, 멈춤)을 적는다.
- 방의 높이는 6칸이다(`boss/boss_view.h`의 `BOSS_VIEW_WALL_H`). 눈높이는 0.5칸이고 뛰어오르면 그만큼 올라간다. 방의 높이는 그리는 쪽의 값이라 계산에는 쓰이지 않는다.
- 뛰어오르기는 서버의 답을 기다리지 않고 키를 누른 순간부터 클라이언트가 그린다(`core/client.c`의 `jump_predict`, `shown_jump`). 높이는 프레임마다 시간에서 구하고, 서버와 같은 식(`boss_jump_curve`)과 같은 `boss/config.ini`를 쓴다. 맞았는지는 서버가 정한다. 올라갈 때보다 빨리 떨어지고, 내려서면 눈이 살짝 주저앉았다 돌아온다.
- 맵은 18 x 18칸이다(`boss/boss.h`의 `BOSS_MAP`. 바깥 벽을 빼면 16 x 16이고 2x2 기둥이 넷 있다). 24칸일 때는 쫓아다니는 길이 너무 길었다.
- 초파리는 평소에 낮게 떠서 날아다니는 것으로 그린다(`boss/boss_view.c`의 `boss_view_fly_lift`). 멈추면 내려앉고, 돌진할 때는 낮게 깔려 달려들고, 달아날 때는 높이 솟는다. 높이는 그리는 쪽이 정하고, 맞히고 맞는 판정은 평면 그대로다.
- 픽셀 그림의 초파리는 처음 구상한 그림(`ui/assets/fly_idle.spr`: 네모난 몸, 양옆의 붉은 눈, 위의 날개, 배의 줄무늬)을 상자 모형으로 옮긴 것이다(`boss/boss_view_hd.c`의 `draw_fly`). 어느 쪽에서 보든 이어진 모습이 나온다.
- 초파리의 도약은 0.5초에 6칸쯤 날아간다(`boss/config.ini`의 `takeoff_scale`, `air_ticks`). 전에는 0.2초에 10칸이라 맞으면 순간이동처럼 보였다.
- 픽셀 그림으로 볼 때 보스전의 상태 표시는 3D 화면 위에 작게 띄운다(둠 같은 1인칭 게임의 배치를 참고했다): 맨 위 가운데에 초파리의 체력, 오른쪽 위에 남은 시간과 지도, 왼쪽 위에 뇌, 왼쪽 아래에 내 체력과 막기, 오른쪽 아래에 무기, 맨 아래에 키 안내 한 줄. 글자 한 줄이 화면 높이의 2%쯤이다.
- 미니게임에서는 오른쪽 위 작은 칸에 `TAB`이라고 적혀 있다(볼 사람을 바꾼다). 로비의 아래 줄에는 준비, 시작, 나가기 키가 있다.

## 화면을 좋게 보기

화면을 터미널에 보내는 방법이 둘 있다. 클라이언트가 시작할 때 터미널에 무엇을 받는지 물어보고 고른다(`--gfx=auto`가 기본값이고 `--gfx=sixel`, `--gfx=cell`로 정할 수 있다).

| 방법 | 언제 쓰나 | 어떻게 보이나 |
|---|---|---|
| 픽셀 그림(Sixel) | 터미널이 Sixel 그림을 받을 때. Windows Terminal은 1.22부터 받는다 | 화면의 실제 해상도로 그린다(2400x1340까지). 글자는 윤곽선 글꼴로, 보스전과 진행자 시프봇과 말풍선은 식으로 그려서 가장자리가 또렷하다. 스테이지의 칸처럼 픽셀로 찍은 그림은 그대로 키운다 |
| 글자 칸 | 그 밖의 터미널 | 글자 한 칸이 픽셀 가로 1개, 세로 2개다. 색 번호 그림을 그대로 보낸다. 한 칸에 색을 둘밖에 못 써서 그림이 픽셀로 보인다 |

터미널 프로필은 `tools/wt_profile.json`에 둘 다 있다. Windows Terminal에 넣는 법:

1. 그 파일을 `%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\SuperSypParty\profile.json`으로 복사한다(폴더가 없으면 만든다).
2. 터미널을 다시 켠다. 켜 둔 채로 두려면 터미널의 설정 파일을 한 번 저장한다(설정을 다시 읽을 때 이 폴더도 읽는다). 프로필 목록에 "Super Syp Party HD"와 "Super Syp Party"가 생긴다.

### 픽셀 그림으로 볼 때

파워셸에서: `wt.exe -F -p "Super Syp Party HD" wsl.exe --cd ~/2026_sysprog -e build/release/client`

- 그림의 픽셀 하나가 화면의 픽셀 하나가 되게 한다. 터미널은 글자 한 칸을 그림의 가로 10픽셀, 세로 20픽셀로 치고 그 비율로 그림을 늘리거나 줄인다. 그래서 글자 칸이 실제로 10x20픽셀이면 1:1이 되어 가장 또렷하다. "Super Syp Party HD" 프로필이 그렇게 맞춘 것이다. 칸이 그보다 크면 터미널이 그림을 늘려서 흐려진다(처음에 1200x670을 2.1배로 늘려 보았더니 뭉개져 보였다).
- 그림의 크기는 240x134의 정수배이고, 창에 들어가는 가장 큰 것을 고른다(10배 = 2400x1340까지). 2560x1440 화면의 전체 화면 창은 256칸 72줄이라 10배가 된다. 1920x1080이면 192칸 54줄이라 8배(1920x1072)가 된다(계산한 값이고 그 화면에서 보지는 않았다). `--scale=N`으로 상한을 낮출 수 있다(6 이하).
- 입장 화면, 지난 랭킹, 로비는 픽셀 그림으로 보낼 때 글자로 찍은 그림으로 그린다(`ui/art.c`). 세 화면이 같은 그림을 쓰고 오른쪽의 글자만 다르다: 화면을 글자 칸 400 x 134로 나눠 칸마다 밝기에 맞는 글자를 찍는다. 받침 위의 유리 돔 안에 시프봇이 서 있고 초파리가 그 위를 돌고 색종이가 내린다. 참가자와 안내는 오른쪽에 작은 글자로 적는다. 글자 칸으로 보낼 때는 전처럼 `screen_lobby`가 그린다.
- 보스전의 배경(바닥, 천장, 벽)은 눈이 움직이는 동안 절반 해상도로 그려 두 배로 키우고, 0.12초 멈춰 있으면 제 해상도로 한 번 그려 두었다가 다시 쓴다(`boss/boss_view_hd.c`의 `draw_background`). 잰 값(2400x1340): 움직일 때 그리기 8~10ms에 0.5~0.7MB, 전에는 28~33ms에 1.3~1.8MB였다. 멈춰 있을 때는 2ms쯤이다.
- 캔버스(240x134)에 그린 화면(규칙 카드, 미니게임, 결과)은 그림의 60% 크기로 가운데에 놓는다(꽉 채우면 글자와 그림이 너무 크다). 캔버스는 그대로 키우고, 글자와 말풍선의 상자만 받아 두었다가 실제 해상도로 다시 그린다(`ui/hd_art.c`). 진행자 시프봇은 그림(.spr)을 바꾸지 않고 같은 그림의 윤곽을 매끈하게 이어 키운다(`ui/hd_art.c`의 `draw_sprite`). 다른 그림은 원래 그림 그대로 키운다. 글자는 윤곽선 글꼴(`ui/assets/font_outline.fnt`, `tools/font_hd.py`로 만든다)이라 어떤 크기에서도 또렷하고, 자리와 폭은 12픽셀 글꼴과 같아서 화면 코드를 고칠 필요가 없다. 스테이지가 자기 칸에 그린 것은 이미 픽셀이라 그대로 키운다.
- 보스전의 벽, 바닥, 기둥에는 재질을 식으로 넣는다(돌의 결과 금, 나무결과 옹이, 쇠띠와 못, 모서리의 입체감, 천장의 들보). 색은 프레임마다 240개로 줄이고, 번지는 명암은 자리마다 정해진 값을 더해 흩는다. 한 색으로 칠한 면(글자, 상태 표시)은 흩지 않는다.
- 재 본 것(11/24, 이 프로필, Windows Terminal 1.25, 발표용 빌드): 2400x1340 한 장을 그리는 데 19ms, Sixel로 적는 데 13ms쯤 걸리고 보스전 한 장이 1.0~1.2MB다. 터미널은 1초에 60MB쯤 받아 줬다. 300만 픽셀이라 줄 단위의 일은 여러 스레드에 나눠 주고(`ui/par.c`), 터미널에 쓰는 일은 따로 스레드에 맡겨 쓰는 동안 다음 장을 그린다. 멈춘 화면은 바뀐 줄만 다시 보낸다.
- 마우스: 터미널은 마우스 자리를 글자 칸으로 알려 주는데 이 방식은 칸이 크다(가로 240칸). 화면에 그리는 시선은 정한 방향을 부드럽게 따라가게 했다(`LOOK_SMOOTH_MS`).
- 전체 화면은 `F11`로 푼다.

### 글자 칸으로 볼 때

터미널의 글자 한 칸이 게임의 픽셀 가로 1개, 세로 2개다. 그래서 글자 칸이 작을수록 한 화면에 픽셀이 많이 들어간다. 보통 글자 크기(가로 9픽셀쯤)로는 배율 1(240x134)이 고작이다. "Super Syp Party" 프로필은 글자 칸을 가로 2픽셀, 세로 4픽셀로 줄인 것이다.

파워셸에서: `wt.exe -F -p "Super Syp Party" wsl.exe --cd ~/2026_sysprog -e build/release/client --gfx=cell --scale=auto`

- `--scale=N`(1~6)은 화면을 N배로 키워 그린다. 터미널이 240N칸 67N줄 이상이어야 한다. `--scale=auto`는 시작할 때의 터미널에 들어가는 가장 큰 배율을 고른다. 2560x1440 화면에서 이 프로필이면 1280칸 360줄이라 5배(1200x670)가 된다(재 본 값).
- 보스전의 3D 화면만 더 촘촘해지고 나머지 화면은 같은 그림이 커진다. 배율 3 이상에서는 보스전의 글자와 상태 줄을 절반 크기로 그린다.
- 이 프로필에서는 글자를 읽을 수 없다. 게임 전용이다.
- 내보내는 양: 가짜 터미널 1200칸 335줄에서 시선을 계속 돌릴 때 1초에 약 1.4MB였다(`ui/present.c`가 바뀐 칸만 내보낸다).

## 진짜 뇌

가짜 뇌 대신 실제 초파리 뇌 배선(FlyWire v783, 뉴런 138,639개)으로 반응을 계산할 수 있다. 스테이지 코드는 그대로다.

```
make brain-data                      (한 번만. 약 135MB를 받아 data/ 에 준비한다)
make brainprobe                      (자극별 반응과 계산 시간을 표로 본다)
make run STAGE=example BRAIN=real    (진짜 뇌로 실행)
make brain-compare                   (대조 실험. 배선을 섞은 뇌를 만들어 진짜 배선과 반응을 나란히 본다)
```

- 지금 진짜 뇌가 계산하는 것: 다가옴(`BR_LOOM_L/R`) → 도주, 방향 전환, 후진. 맛(`BR_SUGAR`, `BR_BITTER`, `BR_SALT`, `BR_WATER`) → 먹기.
- 냄새(`BR_ODOR_*`, `BR_REPEL_*`)와 착지는 진짜 뇌에 연결하지 않았다. 전진은 규칙으로 둔다.
- 짠맛: 표에 짠맛이라고 적힌 뉴런은 진짜 배선에서 먹기를 오히려 늘렸다. 그래서 `BR_SALT`는 먹기를 줄이는 다른 맛 뉴런(LB1e)에 연결했다. 짠맛만 주면 먹지 않고, 단맛과 같이 주면 먹기가 줄어든다(단맛이 아주 세면 다 막지는 못한다). 확실히 막는 것은 쓴맛이다.
- 물은 먹기를 늘리지 않는다(조금 줄인다). 물로 먹게 만드는 규칙은 진짜 뇌에서 통하지 않는다.
- 이 뇌는 어떤 자극에서는 스스로 계속 발화하는 상태(폭주)에 빠진다. 냄새 뉴런이 그래서 연결되지 않았다. 폭주가 감지되면 뇌를 처음 상태로 되돌린다.
- 진짜 뇌로 돌리면 오른쪽 아래 칸이 뇌 지도로 바뀐다. 뉴런을 실제 위치에 놓은 그림이고, 발화가 많은 곳일수록 밝다. 노란 점은 게임이 읽는 출력 뉴런이 발화한 자리다. 아래 막대는 왼쪽부터 왼쪽 회전, 도주, 후진, 먹기, 오른쪽 회전이다.
- 스테이지를 만들 때는 가짜 뇌(`fast`, `slow`)로 충분하다. 올리기 전에 `BRAIN=real`로도 한 번 돌려 본다.
- 대조 실험: 섞은 뇌(`data/shuffled`)는 뉴런, 뉴런마다 보내고 받는 연결 수, 보내는 세기를 그대로 두고 받는 뉴런만 전체에서 섞은 것이다(`tools/brain_shuffle.py`). `BRAIN=shuffled`로 게임에도 붙일 수 있다.
- 섞은 배선에서는 같은 자극을 줘도 출력 뉴런이 발화하지 않아 초파리가 가만히 서 있다. 반응이 코드가 아니라 배선에서 나온다는 것까지는 이 비교로 말할 수 있다.
- 다만 전부 섞으면 감각 뉴런에서 출력 뉴런으로 가는 길이 통째로 끊긴다. 배선의 세부가 얼마나 중요한지는 이 대조로 알 수 없다.

## 가짜 뇌와 진짜 뇌의 차이

같은 자극에 두 뇌가 다르게 반응한다. 발표는 진짜 뇌로 하므로, 수치(`config.ini`)는 진짜 뇌에서도 맞는지 본다.

```
make brain-table BRAIN=real           (자극의 세기별로 두 뇌의 반응을 표로 본다)
make test-stage STAGE=이름 BRAIN=real  (내 스테이지가 서버에서 진짜 뇌로 2라운드를 도는지 본다)
```

| 하려는 것 | 가짜 뇌 | 진짜 뇌 |
|---|---|---|
| 단맛으로 먹게 하기(먹기 0.5 이상) | 단맛 0.5부터, 다음 틱에 | 단맛 0.5부터(0.3은 안 된다), 3틱 뒤에 |
| 쓴맛으로 못 먹게 하기(단맛 1.0일 때) | 쓴맛 0.7부터 | 쓴맛 0.5부터. 0.7이면 거의 0 |
| 짠맛으로 못 먹게 하기 | 단맛 1.0에 짠맛 1.0이면 먹기 0.31 | **단맛 1.0이면 짠맛을 얼마를 줘도 먹는다(0.95).** 단맛 0.5이면 짠맛 0.5부터 줄고 0.7이면 거의 0 |
| 물로 먹게 하기 | 물 1.0이면 먹기 0.51 | **안 된다(0)** |
| 한쪽 다가옴으로 달아나게 하기(달아남 0.5 이상) | 0.5부터, 다음 틱에 | **0.3부터**, 2틱 뒤에. 0.2는 14틱이 걸린다 |
| 한쪽 다가옴으로 반대쪽으로 돌게 하기 | 세기에 비례한다 | 0.3부터 최대다. 1.0이면 뒤로도 간다(0.78) |
| 양쪽 다가옴으로 뒤로 가게 하기 | 뒤로 = 세기 | 양쪽 0.7부터 조금, 1.0이어야 최대다. 그 아래에서는 달아나기만 한다 |
| 냄새, 싫은 냄새 | 반응 없음 | 반응 없음 |

- 진짜 뇌는 반응이 2~3틱 늦게 나온다. 자극을 한 틱만 주면 반응하지 않을 수 있다. 몇 틱 이어서 준다.
- 진짜 뇌는 다가옴에 더 예민하다. 가짜 뇌에서 "아슬아슬하게 안 달아나는" 세기(0.3~0.4)는 진짜 뇌에서 달아난다.
- 음식 고르기처럼 짠맛을 쓰는 게임은 단맛을 0.5쯤으로 낮춰서 같이 준다.

## 스테이지를 새로 만드는 순서

1. `stages/example` 폴더를 자기 스테이지 이름으로 복사한다. 예: `cp -r stages/example stages/swat`
2. `make run STAGE=swat`이 도는지 본다. 다른 파일은 고치지 않아도 된다.
3. `stages/swat/` 안의 C 파일, `config.ini`, `assets/`만 고친다.
4. 올리기 전에 `make bot STAGE=swat`이 통과하는지 본다.

## 꼭 지킬 것

스테이지 코드에서 `rand`, `srand`, `time`, `clock_gettime`, `sleep`, `usleep`, `fork`, `socket`, `pthread_create` 같은 함수를 부르면 빌드가 멈추고 어느 파일의 어느 함수인지 알려 준다(`tools/stage_check.sh`). 난수는 `stage_rng_*`, 시간은 틱 수로 센다.

- 자기 폴더 밖은 고치지 않는다. 헤더(`include/`)를 바꿔야 하면 서진석에게 말한다.
- 유저마다 상태를 따로 둔다. 초파리 상태도 따로 둔다. 예제의 `side_t`를 참고한다.
- 시간은 틱 수로 센다. 한 틱은 0.05초이고 한 판은 `ctx->n_ticks`번 돈다. 시계를 읽거나 `sleep`하지 않는다.
- 난수는 `stage_rng_*`만 쓴다. `rand()`, `time()`은 쓰지 않는다.
- `stage_draw`에서는 그리기만 한다. 상태를 바꾸지 않는다. 초파리 칸에는 모두에게 같은 그림을 그린다.
- `brain_*`는 `stage_tick` 안에서만 부른다. `brain_fired`는 반응하는 동안 계속 1이므로, 한 번만 반응하게 하려면 쿨다운을 둔다.
- 이펙트(`fx_*`)는 사건이 난 틱에 `stage_tick`이나 `stage_input`에서 부른다. `stage_draw`에서 부르지 않는다.
- 난이도 숫자는 코드에 쓰지 않고 `config.ini`에 둔다.
- 점수는 0 이상이고, 한 판을 잘하면 100 근처가 되게 맞춘다.

## 자주 묻는 것 (11/24)

문서끼리 내용이 다르면 저장소가 맞다. 믿는 순서는 `include/`의 헤더 주석, 이 안내, `docs/skeleton-design.md` 6장, 그다음이 예전 전체 정리 문서다.

**폴더와 올리기**

- 새 스테이지 폴더는 그냥 만들면 된다. `stages/` 아래의 폴더는 Makefile이 알아서 찾는다. 다른 파일이나 표에 추가할 것이 없다.
- 자기 브랜치에 올린다. `main`에는 서진석이 합친다. 서버에 넣는 순서(`ORDER`)도 그때 정한다.
- 올리기 전에 `make bot STAGE=이름`과 `make test-stage STAGE=이름 BRAIN=real`이 "통과"인지 본다.

**조작**

- 조작은 WASD로 안내한다. 코드는 `SK_LEFT`, `SK_RIGHT`, `SK_UP`, `SK_DOWN`을 받는다. 코어가 A, D, W, S(와 방향키)를 그 네 키로 바꿔 넘긴다. `stage_info`의 `controls`에는 "WASD"처럼 적는다.
- 조작은 규칙 카드에서 시프봇이 말해 준다. 말풍선의 마지막 줄에 "조작: WASD"처럼 나온다. 앞의 "조작: "은 코어가 붙이므로 `controls`에는 넣지 않는다.
- 마우스를 쓰지 않으면 `stage_pointer`를 만들지 않는다. 빈 함수도 필요 없다. 코어에 기본 구현이 있다.
- 키는 누른 순간에만 온다. 뗀 순간은 오지 않고, 누르고 있어도 한 틱에 한 번만 온다. 이동은 "누를 때마다 한 걸음"으로 만든다.

**한 판의 끝과 생명**

- 스테이지는 일찍 끝낼 수 없다. `stage_tick`은 항상 `ctx->n_ticks`번 불린다. 스테이지 안에서 생명이 다한 참가자는 그 자리에서 멈추고 점수만 고정한다.
- 한 참가자가 멈춘 것이 다른 참가자나 초파리에게 영향을 주면 `make bot`에서 걸린다. 초파리에게도 참가자와 같은 규칙을 적용한다.
- 화면 아래 띠의 `LIVES`는 게임 전체의 기회(3번)다. 스테이지 안의 생명은 자기 칸 안에 따로 그린다.
- 판정은 "내 점수(반올림) >= 초파리 점수"다. 같으면 이긴 것이다.

**뇌**

- `BR_FORWARD`는 읽지 않아도 된다. 배선에서 나온 반응이 아니라 두 뇌 모두 "1 - 다가옴 중 큰 값"이라는 규칙으로 만든 값이다. 속도는 `config.ini`의 기본 속도로 둔다.
- 진짜 뇌의 방향 전환은 다가옴 0.3부터 바로 최대다(세기에 비례하지 않는다). 초파리의 조종은 "얼마나 도는가"보다 "어느 쪽으로 도는가"로 짠다. 좌우를 같이 주면 방향이 꺼지므로 더 가까운 쪽 한쪽만 준다.

**`make bot`이 보는 것** (`tools/bot.sh`. 가짜 뇌 둘, 씨앗 1~6, 1명과 2명과 3명 판)

- 모든 판이 10초 안에 정상 종료한다. 메모리 검사에 걸려도 여기서 실패한다.
- 점수가 0 이상의 유한한 숫자다.
- 같은 씨앗으로 두 번 돌리면 결과가 같다.
- 경고가 없다. 경고가 나는 경우: `config.ini`에 없는 이름을 `cfg_get`으로 읽음, `config.ini`에 읽을 수 없는 줄, 그림 파일이 없거나 틀림, `stage_draw`에서 `fx_*`를 부름, `stage_tick` 밖에서 `brain_*`를 부름.
- 초파리 칸의 그림이 참가자마다 같다.
- 그리기를 틱마다 0번, 2번 불러도 점수가 같다(`stage_draw`에서 상태를 바꾸면 걸린다).
- 3명 판의 각자 점수가, 같은 입력으로 혼자 돌린 판의 점수와 같다. 초파리 점수는 인원에 따라 달라지지 않는다.
- 봇은 무작위로 마우스도 보낸다(`stage_pointer`가 없으면 무시된다). 실패하면 `build/logs/bot_이름.log`를 본다.

**그림**

- 초파리는 코어에 있는 `SPR_FLY_IDLE`, `SPR_FLY_EAT`, `SPR_FLY_JUMP`, `SPR_FLY_HIT`를 그대로 쓴다.
- 자기 그림은 `stages/이름/assets/이름.spr`에 글자로 그린다. 예는 `stages/example/assets/rock.spr`, 형식은 `docs/skeleton-design.md` 6.4에 있다.
- 다른 사람의 화면에서는 내 칸이 절반 크기(47x54)로 보인다. 중요한 것은 2픽셀 이상으로 그린다.

## 화면을 직접 만들 때 (`screens/`)

- `screens/` 안에 `screen_lobby`, `screen_result`, `screen_ranking`, `screen_spectate`를 같은 이름으로 만들면 코어의 기본 화면 대신 쓰인다. 넷 중 만들고 싶은 것만 만들면 된다.
- 직접 만든 화면 위에는 코어가 아무것도 덧그리지 않는다. 화면 전체(240x134)가 자기 것이다. (기본 화면일 때는 코어가 빈 자리에 역대 순위를 그려 넣는다.)
- `make screen SCREEN=lobby CASE=2`로 예시 상태를 넣어 본다.

## 한글 글자

`ui_text`에 한글을 그대로 쓰면 된다(소스 파일은 UTF-8). 스테이지의 제목, 규칙, 조작법도 한글로 적는다. 예제(`stages/example/example.c`)를 참고한다.

- 한글 한 글자는 12x12칸, 영문과 숫자는 6x8칸이다. 폭은 `ui_text_w`로 잰다.
- 한글이 섞인 글자열은 한 줄의 높이가 12픽셀이다. 그때 영문과 숫자는 3픽셀 내려서 한글의 가운데 높이에 맞춰 그린다. 영문만 있는 글자열은 예전과 같다.
- 한글은 12픽셀을 꽉 채운다. 여러 줄을 쓸 때는 줄 간격을 14픽셀로 잡는다. 12픽셀이면 위아래 줄이 맞닿는다.
- 그릴 수 있는 글자: 한글 음절 전부(11172자), 낱자모(ㄱ~ㅣ), 그리고 `· × ‘ ’ “ ” … ← ↑ → ↓ ★ ♥`. 이 부호들도 12x12 한 칸을 차지한다. 한자 같은 그 밖의 글자는 빈칸이 된다.
- 획이 많은 글자(뷁, 꿿 등)는 12픽셀에서 뭉개진다. 안내 문장에는 흔한 글자를 쓰고 `make run`으로 한 번 읽어 본다.
- 제목, 규칙, 조작법은 서버를 거치면서 각각 31, 95, 47바이트까지만 전달된다(한글은 한 글자가 3바이트). 넘치면 글자 단위로 잘린다. `stage.h`에 적힌 글자 수를 지키면 넘치지 않는다.
- 글꼴은 Freesentation(프리젠테이션체, SIL Open Font License 1.1)이다. 저작권 표시와 라이선스 전문은 `ui/assets/FONT_LICENSE.txt`에 있다.

글꼴 파일(`ui/assets/hangul12.fnt`)은 저장소에 들어 있어서 따로 준비할 것이 없다. 파일이 없으면 한글이 빈 네모로 보이고 로그에 경고가 남는다. 다시 만들 때만 아래를 돌린다(`data/venv`는 `make brain-data`가 만든다).

```
(https://freesentation.blog/freesentation 에서 ver 2.001을 받아 data/raw/font/ 에 푼다. 글꼴 파일은 저장소에 올리지 않는다)
data/venv/bin/python -m pip install freetype-py
data/venv/bin/python tools/font_convert.py data/raw/font/Freesentation-4Regular.ttf ui/assets/hangul12.fnt --preview build/font_preview.ppm
```

굵기, 크기, 그리는 방식을 바꿔 보려면 `tools/font_convert.py` 맨 위의 설명과 `--mode`, `--ppem` 옵션을 본다. `--preview`는 예문을 그린 그림(PPM)을 만든다.
